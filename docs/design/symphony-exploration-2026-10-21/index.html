Design prototype · Sample data

Three layouts for Symphony, without the board

Each concept puts a different thing at the centre of the screen. They share the same sample work item, statuses and evidence rules, so you can compare structure rather than styling. None has been chosen.

Sample task NEO-4821, Preserve queued sends across reconnects Attempt 3, head 7f3a9c2 One open decision, D-3

  1. A. Runs

    Run-first operating view. Candidate default for daily operations.

    Centre
    A searchable list of runs, with Needs you pinned above it and a side panel for the selected run.
    Good at
    Many runs at once, fast triage, one clear blocker and next step per run.
    Weaker at
    Showing how the stages, packages and repair rounds inside one run relate to each other.
    Open runs

  2. B. Workflow map

    Workflow-first map for one work item. Candidate detailed execution view.

    Centre
    A stage map from Intake to PR: two parallel packages, critics and testers, a bounded two-round review, and a human merge gate. An inspector shows the selected step.
    Good at
    Explaining where one run is stuck, what was sent back and which agent did what.
    Weaker at
    Overview of many runs. Runs are reached through a small switcher.
    Open map

  3. C. Plan and decisions

    Plan-and-decisions workspace with a compact run and agent rail. Candidate planning surface.

    Centre
    The canonical plan, editable with revisions, beside a Decisions view that keeps draft answer, saved decision and execution approval separate.
    Good at
    Recording why work is shaped the way it is, and making sure no edit or answer silently starts work.
    Weaker at
    Live operations. It assumes you already know which run you are planning.
    Open plan

The concepts can complement one another later. This page compares them as candidates for the primary layout. Rationale, tokens, status rules and limits are in DESIGN.md.

Static HTML, CSS and JavaScript. No network, tracker, server or agent is connected. Actions change local demo state only and reset on reload or with Reset demo.
