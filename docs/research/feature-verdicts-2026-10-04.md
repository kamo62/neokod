# Neokod feature comparison, updated 4 October 2026

Current revision: 2 (4 October 2026, dashboard and canonical-document consolidation).

This is the decision view requested after “Review T3Code nightlies and PRs”. Implementation status belongs in [plan.md](../../plan.md). Local source was rechecked at `da7655bb2e3964c800eec882360e7d1d0eb4ca25`, preserving the owner's working-tree changes. Earlier [seventeen-product research](competitor-codebase-review-2026-10-04.md), [source manifests](evidence/competitor-source-manifests.json), issue qualifications and measured local fixtures remain the evidence base.

The user has now reopened the local-only restriction. The first remote scope is their own/work machines. The required journey is discussion on the laptop, explicit continuation on a server, the right repository/code/context on that server, and progress/results linked back to the originating chat. A remote connection picker alone does not satisfy that journey. Shared multi-user servers are a later scope.

## Decision

T3 leads Neokod in implemented in-chat orchestration and new-run environment selection. Paseo is another strong orchestration reference and explicitly documents cross-host execution. MonoCode is a strong additional reference for integrated own-machine remote sessions and durable request receipts; Orca offers broader supervised cross-host dispatch. Synara is the strongest inspected reference for presenting task context, delivery and children around a central chat. Empryo contributes code intelligence and explicit child briefings, with a material public-v2/private-v3 boundary. Superset and Agent Orchestrator offer different board strengths. Orca has a stronger explicit terminal flow-control design. No evidence establishes one overall winner in speed, recovery, security or reliability.

The model/usage dashboard review below covers all twenty products. T3 is the strongest combined history/limits/environment reference; Oh My Pi leads on deeper local analytics. Agent Orchestrator and OpenCodeX contribute stronger accounting provenance, while Synara, Paseo and bb inform account freshness. Neokod has a genuine historical-usage gap and should retire the unused quota and financial-projection paths as the feature lands.

Choose the best demonstrated mechanism for each Neokod capability. Retain Neokod's existing ownership, evidence, provider and client-runtime machinery where it already solves the problem. New UI remains an independently designed Neokod UI. Remote access is now a deliberate product assessment, rather than being discarded under the earlier local-only filter.

## T3: what its new orchestrator actually gives us

Current selected source was fetched at `b3b6ae2cebbae39a706038911dbb8c85c7120be7`. T3's positive reception is a useful signal to investigate, not measured reliability evidence. Its product lead is real in the inspected paths.

The provider conversation can delegate through MCP. The service validates the active parent, resolves a registered provider/model and records the parent thread/run/node. Deterministic IDs create child threads/task nodes; event and effect persistence provides a durable execution path. Results have delivery and acknowledgement states. No separate coordinator model or mandatory orchestration mode is inherent in this mechanism. [Delegation service](https://github.com/pingdotgg/t3code/blob/b3b6ae2cebbae39a706038911dbb8c85c7120be7/apps/server/src/mcp/OrchestratorMcpService.ts#L1369), [child lineage](https://github.com/pingdotgg/t3code/blob/b3b6ae2cebbae39a706038911dbb8c85c7120be7/apps/server/src/orchestration-v2/Orchestrator.ts#L6318), [durable effects](https://github.com/pingdotgg/t3code/blob/b3b6ae2cebbae39a706038911dbb8c85c7120be7/apps/server/src/orchestration-v2/EffectOutbox.ts#L199).

Machine selection is a separate path. Environment-scoped clients and composer project matching select where new work runs. Populated/active threads lock that environment. Its current delegate target carries provider/model/options, with no `environmentId`; children inherit the parent's project/workspace. Therefore new-run machine selection is established, but automatic cross-machine children or seamless active-session migration are not established by this API. [Composer environment binding](https://github.com/pingdotgg/t3code/blob/b3b6ae2cebbae39a706038911dbb8c85c7120be7/apps/web/src/components/ChatView.tsx#L2944), [inherited child workspace](https://github.com/pingdotgg/t3code/blob/b3b6ae2cebbae39a706038911dbb8c85c7120be7/apps/server/src/orchestration-v2/SubagentProjection.ts#L42).

T3 supports endpoint, SSH and relay targets. SSH includes remote bootstrap/version checks and a local forward to the remote loopback listener. That is substantially more complete than a pasted URL alone. It is worth comparing to other competitors, rather than adopting its transport wholesale. [Connection types](https://github.com/pingdotgg/t3code/blob/b3b6ae2cebbae39a706038911dbb8c85c7120be7/packages/client-runtime/src/connection/model.ts#L9), [SSH implementation](https://github.com/pingdotgg/t3code/blob/b3b6ae2cebbae39a706038911dbb8c85c7120be7/packages/ssh/src/tunnel.ts#L1100).

Current issue metadata still marks [plan-mode authority widening](https://github.com/pingdotgg/t3code/issues/15503), [child notices cancelling queued Claude tools](https://github.com/pingdotgg/t3code/issues/15351), [queued/waiting keep-alive](https://github.com/pingdotgg/t3code/issues/15289) and [child usage attribution](https://github.com/pingdotgg/t3code/issues/15429) open. These are qualified reports, not reproduced failures here. Keep their acceptance lessons without dismissing the feature lead.

## MonoCode: a close own-machine remote reference

Inspected SHA: `271b66ded71e795e0569db77c9bbf599219c8cdc`, committed 4 October 2026 at 10:35:15 UTC. It is a desktop agent-CLI workbench with an experimental remotely owned host runtime and an [MIT licence](https://github.com/hardbeat920/monocode/blob/271b66ded71e795e0569db77c9bbf599219c8cdc/LICENSE). Its integration is closer to Neokod's proposed desktop workflow than CodexMonitor's global remote-host mode.

Explicit child permission overrides need their own ceiling.                                      |
| Handoff        | Local provider switching offers a reviewable recap; deterministic fallback has a 1,800-character brief budget.                                                                         | Does not transfer local HEAD/dirty code or move the current chat to another machine.                                                                             |

The strongest inspected mechanism is [host admission](https://github.com/hardbeat920/monocode/blob/271b66ded71e795e0569db77c9bbf599219c8cdc/host/engine.ts#L414). It hashes the parsed command, checks an existing receipt, atomically saves the session mutation and receipt, then starts the effect. Conflicting payload reuse fails. This directly supports Neokod's accepted-versus-started distinction and uncertain-reply recovery. [Effect ordering](https://github.com/hardbeat920/monocode/blob/271b66ded71e795e0569db77c9bbf599219c8cdc/host/engine.ts#L690), [receipt conflict](https://github.com/hardbeat920/monocode/blob/271b66ded71e795e0569db77c9bbf599219c8cdc/host/store.ts#L238), [restart handling](https://github.com/hardbeat920/monocode/blob/271b66ded71e795e0569db77c9bbf599219c8cdc/host/engine.ts#L270).

Per-device credentials are hashed and revocable; server authentication precedes body processing and checks the persisted host identity. Native storage keeps the token outside renderer metadata, accepts HTTPS or loopback HTTP, and uses a restricted file rather than an OS keychain. Credentials still grant the host OS user's authority. [Device credentials](https://github.com/hardbeat920/monocode/blob/271b66ded71e795e0569db77c9bbf599219c8cdc/host/store.ts#L277), [server checks](https://github.com/hardbeat920/monocode/blob/271b66ded71e795e0569db77c9bbf599219c8cdc/host/server.ts#L200), [native connection storage](https://github.com/hardbeat920/monocode/blob/271b66ded71e795e0569db77c9bbf599219c8cdc/src-tauri/src/remote.rs#L40).

Its local orchestrator records dispatch before resource creation and bounds workers, tasks and mutating receipts. However, result wakeup marks a result delivered before submitting a lead continuation, with failure callbacks restoring the flag. There is no inspected recipient acknowledgement token; this is not the cross-host result-delivery contract Neokod needs. [Local admission](https://github.com/hardbeat920/monocode/blob/271b66ded71e795e0569db77c9bbf599219c8cdc/src/features/orchestration/model/orchestration.ts#L1465), [result wakeup](https://github.com/hardbeat920/monocode/blob/271b66ded71e795e0569db77c9bbf599219c8cdc/src/features/orchestration/model/orchestration.ts#L1980).

The remote transcript uses changed blocks and bounded consistent-revision chunks, a useful network/refresh pattern. Transfer slots retain entire serialised revisions in memory, so per-response caps do not prove bounded total memory or superior performance. [Sync transfer](https://github.com/hardbeat920/monocode/blob/271b66ded71e795e0569db77c9bbf599219c8cdc/host/sync-transfer.ts#L12). The [remote scope](https://github.com/hardbeat920/monocode/blob/271b66ded71e795e0569db77c9bbf599219c8cdc/docs/remote-access.md#L101) and [provider recap](https://github.com/hardbeat920/monocode/blob/271b66ded71e795e0569db77c9bbf599219c8cdc/src/features/sessions/model/handoff.ts#L53) make the missing exact-code transfer and originating-chat return explicit. No MonoCode build, provider run or SSH session was executed here.

## Self-managed remote execution: decision to make

The selected first scope is one developer's own/work machines. These are design judgements from source, not runtime superiority claims.

The current canonical plan records a Tailscale-first preference. Preserve that: independent Neokod servers reached through authenticated private endpoints are the first candidate for that setup; desktop-owned SSH tunnels are an alternative informed by Orca, Paseo and T3. It reuses the current environment registry and keeps execution facts on the owning host. Compare this with bb's central-history/multiple-executor alternative in a bounded prototype before committing to a topology. A browser cannot manage native SSH merely because the desktop can: browser use needs a reachable private endpoint or explicitly configured self-hosted transport bridge. Hosted relay and shared tenancy remain separate choices.

### The user's “throw context to my server” workflow

1. Discuss/plan in a local chat. Select Continue on… and choose a registered execution environment and target checkout/worktree.
2. Review an explicit manifest: task and acceptance criteria, source thread/result provenance, repo remote plus exact commit, selected dirty patch/untracked assets, contextual messages/files, target provider/model and effective authority. Never imply a transcript recap is complete provider-native state.
3. Quiesce the source execution if this is continuation, capture a recovery checkpoint and offer the manifest under a durable handoff ID. The remote host resolves its own credentials and validates repository identity and transfer integrity.
4. Prepare the exact base checkout, apply selected changes, verify the resulting tree and acquire its workspace ownership. Fetch failures, missing commits, conflicts or unavailable providers return actionable refusal/preparation states.
5. The target durably acknowledges preparation. The source records a transfer grant bound to that target, manifest hash and ownership generation; the target accepts it once and creates one attempt/new native session. There is no cross-server SQL transaction. Lost acknowledgement means unknown until reconciled, not permission to launch again elsewhere. Returning execution locally requires target settlement/release and a new grant.
6. Show target-machine progress, approvals, diff, tests and PR evidence through links in the originating chat. Return one acknowledged outcome. Disconnecting the laptop does not implicitly cancel the server job; Stop remains a routed, confirmed action.

Do not automatically copy a live provider home, credentials, ignored files or an entire working directory. Do not auto-commit/push merely to make transfer easier. Selected uncommitted changes can travel as a bounded, hash-verified bundle; fetching an existing committed revision is the simpler first subcase. An unpushed/inaccessible base commit needs explicit transfer or refusal. Remote credentials remain remote.

This design combines environment selection, deliberate context handoff and existing ownership/evidence. It does not require a whole engine rewrite or a hosted Neokod cloud.

### Mechanisms worth taking, and defects worth avoiding

T3 separates history scans from account-limit refresh and lets environments finish independently. Its source fingerprinting avoids repeatedly counting shared files; Cursor account totals deduplicate when the same account is accessible on two machines. It discloses unpriced activity and API-equivalent cost. Preserve these ideas when adding Neokod's machines. Do not sum an account-wide endpoint over machines, and do not treat the arithmetic average of two plans' utilisation as available capacity. Its fork-copy timing rule is useful evidence to investigate, not the durable event identity Neokod should promise. [History service](https://github.com/pingdotgg/t3code/blob/b3b6ae2cebbae39a706038911dbb8c85c7120be7/apps/server/src/usage/UsageService.ts#L224), [environment merge](https://github.com/pingdotgg/t3code/blob/b3b6ae2cebbae39a706038911dbb8c85c7120be7/packages/shared/src/usageMerge.ts#L195), [pool arithmetic](https://github.com/pingdotgg/t3code/blob/b3b6ae2cebbae39a706038911dbb8c85c7120be7/packages/shared/src/usageLimits.ts#L422), [fork parser](https://github.com/pingdotgg/t3code/blob/b3b6ae2cebbae39a706038911dbb8c85c7120be7/apps/server/src/usage/usageTranscripts.ts#L197).

Oh My Pi imports changed transcripts incrementally, commits facts with the parser cursor, and serves clean hourly rollups alongside raw dirty hours. Indexing/SSE progress explains partial availability; this is a better performance reference than rescanning history during every page render. Its cost schema still treats an absent model catalogue card as a real zero. Orca's entirely unpriced cost remains null and its partial coverage is labelled. Neokod should combine the incremental mechanism with stricter coverage. [OMP ingestion](https://github.com/can1357/oh-my-pi/blob/6d8552d7f9df1852826923f07f0eed4fe29511f3/packages/stats/src/aggregator.ts), [OMP unpriced predicate](https://github.com/can1357/oh-my-pi/blob/6d8552d7f9df1852826923f07f0eed4fe29511f3/packages/stats/src/db.ts#L38), [Orca partial-cost projection](https://github.com/stablyai/orca/blob/3cc5e1dac659ffd163b81b28261cd843261f4ca5/src/renderer/src/components/stats/usage-overview-model.ts#L29).

Agent Orchestrator's nullable counters, durable file generation/cursor and observed-versus-inferred billing provider are useful storage contracts. OpenCodeX goes further on inference-proxy attempts: logical requests, physical sends, model identity, cache provenance, unpriced/unmetered coverage and read failures. Use those semantic distinctions at Neokod's existing canonical provider boundary, not a second provider runtime. Hermes demonstrates why storage alone is insufficient: its live model-route facts are richer than the dashboard's primary-session grouping. [AO usage domain](https://github.com/Untrivial-ai/agent-orchestrator/blob/b2461dc5955bb11b4ee1213871e6a2157e68da0e/backend/internal/domain/usage.go#L82), [OpenCodeX summary contract](https://github.com/lidge-jun/opencodex/blob/06841165f884a9176d701310638b2112aca7a514/src/usage/summary.ts#L28), [Hermes model writer](https://github.com/NousResearch/hermes-agent/blob/64ad33e32dadbdb462468c7384aa38e5c99a1b7a/hermes_state_usage.py#L305), [Hermes dashboard queries](https://github.com/NousResearch/hermes-agent/blob/64ad33e32dadbdb462468c7384aa38e5c99a1b7a/hermes_cli/web_routers/analytics.py#L87).

Synara is a strong account-fetch reference: five-minute fresh cache, shorter degraded cache, coalesced concurrent refresh, account scope and last-good snapshots that keep their original observation timestamp during backoff. Paseo binds quota discovery to the launch; bb measures selected resources in bounded batches and distinguishes offline, never measured and stale. Neokod should refresh at the server boundary, not launch a provider probe per connected client. Do not let a stale reset timestamp become proof of restored allowance, as MonoCode's headroom helper currently can. [Synara cache](https://github.com/Emanuele-web04/synara/blob/5f2ee77ae9fc60993db47e81419c1171a99a5c32/apps/server/src/providerUsage/index.ts#L92), [stale retention](https://github.com/Emanuele-web04/synara/blob/5f2ee77ae9fc60993db47e81419c1171a99a5c32/apps/server/src/providerUsage/rateLimitResilience.ts#L85), [Paseo launch query](https://github.com/getpaseo/paseo/blob/8216e86ecb92e9b6a39422b12dde8b70a619483e/packages/app/src/usage/queries.ts#L170), [bb bounded fetch](https://github.com/get-bb/bb/blob/4d15c1da0a848fa4834c1e5d0480a0891683bbe9/plugins/provider-usage/server.ts#L287), [MonoCode reset assumption](https://github.com/hardbeat920/monocode/blob/271b66ded71e795e0569db77c9bbf599219c8cdc/src/features/providers/model/accountUsage.ts#L35).

Superset provides a useful conventional chart/drilldown layout, but a cost display cannot claim zero paid spend merely because the intended route is subscription-backed. Its data accepts reported API/harness costs and its UI still hard-codes zero. ### Recommended Neokod experience

Add one Usage destination with Overview, Limits and Models views. Keep the default modest: activity and API-equivalent cost over a stated period, model/provider and project breakdowns, cache data where measured, and an explicit coverage/freshness summary. Filtering by execution environment matters as soon as server runs exist. Model selection should continue using the existing picker/settings; the Models view explains usage and available capabilities, linking back to those controls.

Limits should show each provider account's native window/unit, remaining or used value, reset, plan, last observation and refresh state. Do not combine requests, credits, dollars and percentages into one ring. Do not merge accounts by email or add the same account twice because it is logged in on two machines. If account identity cannot be established, disclose separate sources and incomplete deduplication rather than guessing.

In chat, keep current context separate from a compact account-limit indicator and a Usage link. A per-task drilldown should explain root, child, retry and auxiliary usage, selected versus effective model, execution host and price basis. Show only evidence supported by the provider. A heatmap, streak score, “productivity” metric, account auto-switching or automatic budget enforcement is not needed to deliver this feature.

For the laptop-to-server workflow, retain the original usage facts on their execution host and federate summaries through the existing environment clients. One unavailable server yields a labelled partial total with its last observation; other machines remain usable. Account-wide provider history and app-originated run facts can overlap, so offer clearly scoped views and reconcile identities before combining them. A transferred task keeps lineage while each new attempt records its own host and native session. Do not charge both copied parent history and the original run, or both provider-native aggregate children and separately imported child records.

### Foundation and debt to include in the canonical plan

This is an addition to the existing canonical plan's provider/reliability and environment work, not a second implementation tracker. The sequence is: preserve and normalise usage facts at the canonical event boundary; project account limits independently; add bounded aggregate queries and the minimal page; then add optional existing-history import and cross-machine federation. Historic imports should be opt-in to a declared source scope, incremental and resumable, not a full scan on opening a page or subscribing to WebSocket state.

Preserve source event/native session identity, environment, provider instance and account scope, attempt/turn/child lineage, occurrence and observation times, effective model, billing route when known, and counter semantics. For cumulative counters, record deduplicated deltas with explicit reset/generation handling. Known zero, absent, estimated and incomplete must remain distinguishable. Cache reads can be part of input, and reasoning can be part of output; provider-specific normalisation must prevent counting these twice. A driver kind is not an account identifier.

Keep raw provider cost separately from calculated API-equivalent cost. Record price source/version/currency and whether an estimate uses the rate at the time of the request or a later user override. A saved override must not rewrite the observed effective model or provider-reported amount. Missing prices remain unpriced; missing telemetry remains unmetered. Fixed subscription payments are not implied by per-token estimates.

Retire the unused quota-to-UI path, untyped/unprojected financial events, zero-filtering of legitimate snapshots and repeated per-client probes as this feature lands. Replace the latter with server-owned cached/coalesced refresh, bounded concurrency, genuine cancellation/timeouts, last-good observations and explicit stale/error states. Do not introduce a generic plugin registry, second event bus or separate metrics database until an actual scale/dependency need is measured.

The meaningful acceptance evidence is unchanged totals after replay/reconnect/restart; correct model attribution after a mid-chat switch; known-zero versus missing telemetry; provider cache/reasoning subsets counted once; child/retry cost counted once; accurate timestamp/range boundaries; no invented price; two machines sharing one account deduplicated only where identity is proven; an offline machine shown as partial; and concurrent clients causing one provider refresh. Verify import progress and bounded query/scan work with a representative history fixture, then exercise the actual dashboard. Source contracts alone do not complete those gates.
