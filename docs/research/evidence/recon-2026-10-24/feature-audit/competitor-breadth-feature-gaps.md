The comparison covers twenty products and selected feature families, not exhaustive feature parity. Neokod already has production Git/worktree/PR/diff flows, terminal sessions with byte/line-capped persisted history, indexed workspace file search, thread-title/project/branch search, current context occupancy, selected provider quota/usage facts, provider-specific skills/MCP, and a Symphony work board with lifecycle/recovery evidence. The plan already distinguishes the major work: owner-machine continuation is W5/Track B; GitHub Issues to originating-chat handoff is W6/Track C with partial foundations; ordinary-chat managed children and their worktree isolation are separate W6-C1–C6 scope, gated on formal core exit. Historical usage remains planned under U-1–U–7 and held by §13.2 until Tracks A–C are complete.

The T3 evidence adds candidates, not new implementation authority: #10439 for in-thread find, #18429 for a bounded terminal subscriber budget, #18467 and related schedule fixes, and #15057 with related PR-watch/settlement/cleanup work. Neokod has adjacent search, terminal, turn-settlement and Symphony PR-refresh paths. These do not establish the candidate features as absent. Gateway billing, fleet/cloud-machine control planes, hosted relay, shared tenancy and upstream UI remain excluded or slice-specific; Traycer's host and Empryo v3 remain unavailable evidence.

**Local-first fit:** High for bounded child execution in the same local environment; provider-native tools and Neokod-managed children must remain separate evidence types.
**Minimal reuse/design:** Follow W6-C1–C6 through contracts, persistence, current provider/session authority, immutable result pin, queued wake and contextual tree. Reuse existing runtime item projection and session/runtime ownership; do not route chat delegation through Symphony.

W6 C1–C3 acceptance includes request replay/refusal, caps/depth, exact base and dirty-state evidence, provider/runtimeMode checks, Stop/restart unknown states, durable result return from one observed local OpenCode child; expand adapters only after live probes.
**Verification needed:** Focused repository/contract/MCP tests; composed layer boot; crash at launch/delivery; Stop race; reconnect/restart no duplicate result; one user-visible result in parent; provider native observations remain distinguishable.
**UI rule:** Use competitor flows as interaction evidence only. Keep Neokod’s own normal-chat components and existing SubagentsPanel; no upstream UI port.
**Evidence limit:** Competitor source/docs were not executed. A screenshot or provider child card is not proof of app-managed admission or durable result delivery.
