## 7. Semantic-depth ceiling and gates

What the PR evidence actually supports:

- Census completeness: 3,927 of 3,927 for the closed-date window. PRs that are still open are out of scope.
- File lists: 3,861 complete, 61 truncated at 100 (sample only), 5 unavailable (unknown, not zero).

- Ancestry: positive for 2,774 merged-to-`main` rows and for 332 stacked rows (once the correction lands). Parent-PR inference covers 174 more. Ancestry proves source inclusion in the nightly. It does not prove the behaviour is enabled, survived later reverts, is in a stable release, or ran.
- Unmerged (644): "this PR was not merged". An equivalent change may have shipped through a successor or the V2 rewrite (`reference-only-upstream-v2`, `obsolete-orchestrator-v2-rewrite` 35).

Gates that must accompany any option:

- Formal core exit remains OPEN (§16.18).
- W6-C1–C3 managed children stay CLOSED until core exit, then C4–C6. The feature claim needs closure, Stop and restart tests plus one live OpenCode result (§16.6). Neokod currently refuses OpenCode 2.x (§16.18), so that live proof also depends on a supported runtime.
- Managed children are distinct from Symphony's autonomous tracker pull, and native subagent cards are observations only. Symphony execution is Codex-only (`AgentRuntime.ts:470–480`).
- W5 owner-machine work needs token, pinning and no-fallback rules. Exclude relay, cloud accounts, mobile and shared tenancy.
- §13.2 holds usage (section 12), W8 adapters beyond GitHub Issues, and competitor features outside tracks A to C, unless the owner lifts the hold.
- No upstream UI port. Upstream changes are ports of intent against Neokod code only.
