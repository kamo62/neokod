## What should be retained

LegendList virtualisation plus structural sharing of timeline rows (`MessagesTimeline.tsx:485,1695`); settled highlight cache bounded to 500 entries and 50 MiB (`ChatMarkdown.tsx:122`); diff pool bounded to 2–6 workers, 240 AST entries and 1,000-character tokenisation lines (`DiffWorkerPoolProvider.tsx:48`); existing scoped client runtime, persisted drafts and terminal ownership; server-owned board column mapping and explicit terminal outcomes in `ProjectBoard.ts:12,60`; revision-conditioned project settings save. These are useful foundations, not a reason to add equivalent parallel systems.

## Existing board and delivery semantics

Neokod has five lifecycle columns: Not Started, In Progress, Testing, PR / Human Review and Done. Failed and cancelled items share Done but retain an explicit outcome. This is a server-owned execution board, not an external status mirror. The BoardTab has dispatch buttons and issue links; no drag/drop mutation was found in the reviewed path. Seven adapters can supply candidate work, but reference-based chat intake and host-owned generic tracker state/comment write-back are absent. Local board transitions must not be presented as Jira/Linear/Projects status transitions.
