Open PRs are outside this window.

## What Neokod already has

Inspected production source includes Git branches/worktrees/diffs/PR actions, an embedded terminal with bounded history, workspace file search, a context meter, selected provider quota facts, provider-specific skills/MCP paths and Symphony Work/Attention/Evidence/History. Those are not missing features. Source presence does not establish complete live acceptance.

Normal chats delegate conversationally. Provider-native child cards observe those providers' activity. Future app-managed chat children require W6-C admission, workspace ownership, durable results and acknowledged delivery. Symphony independently pulls work under policy and asks for help when needed. These are distinct execution paths, not interchangeable proof of orchestration.

## Review reconciliation

Sol accepts the reconciled census and bounded competitor inventory, but rejected the preliminary PR dispositions: mixed changes were excluded from truncated samples, positive stacked ancestry was discarded and unavailable sizes became zero. Opus independently reproduced those findings and extended them to complete mixed listings and bare “connect” keyword exclusions. The corrected ledger retains245complete mixed rows as backend-unassessed and59explicit exclusions, with593unassessed backend rows overall. Sol identified #23282 as local webhook filter/template logic without established hosted dependency; Opus explicitly agrees its earlier exclusion acceptance was wrong. The row remains unassessed and is not promoted. Both verified the corrected predicate, receipts and totals.

Opus also corrected the feature matrix's mechanical product-to-gap source joins. A T3 orchestrator source does not support usage, search or terminal claims. Feature-specific evidence is required. PR watch/settle, schedules, in-thread find and terminal output budgets must be fed back from the T3 census into the comparison.

Where priorities differed, the canonical plan wins. Sol's presentation placed usage early; Opus correctly identified the §13.2 hold until Tracks A to C. Usage remains planned and held. G04 is existing Track C handoff work, not a newly invented architecture. No routine approval is requested by this report and no held feature implementation was started.

Researchers: direct first-party Sonnet 5.5 high produced the preliminary PR ledger and selected source evidence before hitting its session limit. The available Luna substitute completes the report and comparison because requested Luna 6.1 is unavailable. Independent review used Sol 6.1 high and direct-Claude-first Opus 5.5; account limits required the authorised Copilot Opus 5.5 high fallback. Exact selected route/effort and partial-versus-complete results are in receipts. Catalogue selection attests the configured identifier, not a separately inspected backend serving model.
