The strongest transferable ideas are durable acceptance separate from launch, capability evidence tied to the active provider/native session, explicit descendant ownership, fair durable message delivery, and bounded background work. No application changes, competitor code execution, package installation, provider requests, tracker mutations, commits or publishing occurred. ## Neokod baseline and product contract

The relevant current path is [apps/server/src/ws.ts](/Users/kamogelo/Code/t3code/apps/server/src/ws.ts:1217) → [apps/server/src/symphony/HandoffService.ts](/Users/kamogelo/Code/t3code/apps/server/src/symphony/HandoffService.ts:490). `delegateFromThread` validates that a source thread exists, resolves a Symphony workflow, allocates a random work-item ID, records `source: manual` and `trackerIssueId: delegated-<id>`, then returns that ID. This is useful scaffolding, but it does not implement a configured tracker identity lookup, request replay identity or a durable originating-message/result link. I found no ordinary-chat frontend caller of this specific operation in the searched web paths. The user requirement should therefore extend the server intake, with chat as a thin adapter, rather than turn this random manual row into a Jira surrogate.

There is already substantial machinery to reuse:

- [apps/server/src/symphony/Persistence/Layers/WorkItemRepository.ts](/Users/kamogelo/Code/t3code/apps/server/src/symphony/Persistence/Layers/WorkItemRepository.ts:259) uses a unique `(project_id, tracker_kind, tracker_issue_id)` key and fenced claim updates. Polling and chat intake must converge on the same canonical work item before preparing a run, rather than maintaining separate claim registries.
- [apps/server/src/symphony/Persistence/Layers/WorkspaceOwnershipRepository.ts](/Users/kamogelo/Code/t3code/apps/server/src/symphony/Persistence/Layers/WorkspaceOwnershipRepository.ts:67) canonicalises paths and uses generations/leases, while [apps/server/src/symphony/HandoffService.ts](/Users/kamogelo/Code/t3code/apps/server/src/symphony/HandoffService.ts:118) waits for a stopped runtime to exit before takeover. This should be the common cross-mode ownership boundary, extended to concrete writer/run identity where needed. Source inspection alone does not prove it prevents every same-mode duplicate writer.
- [apps/server/src/orchestration/RuntimeItemProjection.ts](/Users/kamogelo/Code/t3code/apps/server/src/orchestration/RuntimeItemProjection.ts:103) distinguishes detached/unconfirmed work as orphaned; [apps/server/src/orchestration/RuntimeItemProjection.test.ts](/Users/kamogelo/Code/t3code/apps/server/src/orchestration/RuntimeItemProjection.test.ts:112) covers orphaning, late provider truth and old session generations. New workstream views should reuse those semantics, not invent completed labels/timestamps in the browser.
- [packages/contracts/src/providerRuntime.ts](/Users/kamogelo/Code/t3code/packages/contracts/src/providerRuntime.ts:115) explicitly says a process exit does not establish provider termination. [apps/server/src/provider/Services/ProviderRegistry.ts](/Users/kamogelo/Code/t3code/apps/server/src/provider/Services/ProviderRegistry.ts) owns install/auth/version/model snapshots; capabilities and budgets must remain per provider instance/native session.
- Symphony already owns scheduler/validation/evidence/review/merge flow. [docs/architecture/symphony.md](/Users/kamogelo/Code/t3code/docs/architecture/symphony.md) says execution is currently Codex-only and names parsed-but-unenforced limits. Ordinary chat intake must preserve configured board and merge policy without advertising those future keys as enforcement.

Concrete intake contract to build: `Send Jira ABC-123 to Symphony` resolves only through the existing server-configured Jira connection and its immutable issue ID. Store originating thread/message, tracker connection/project/key/ID, returned work item, request identity and the resulting run/evidence/PR links durably. Retrying the same request returns the same work item; a poll racing chat cannot create a second one. If the tracker or identity is unavailable, report that and do not create a guessed manual task. Launch remains an independently observed phase.

Chat workstreams should expose parent/child provenance, role, provider instance, effective model, branch/workspace, current phase and attributed updates. Runtime server facts own start/end/last-observed times. Parent settlement with a potentially surviving child must render orphaned/tracking lost or known child-active evidence. A restart does not reset elapsed operation time to the current browser mount. Symphony remains the tracker execution destination and review board, accessible from the same ordinary chat.

The following paths describe the frozen default branch, not a claim about that released binary.

Four concrete paths:

1. Durable acceptance precedes launch. [src/main/runtime/rpc/methods/orchestration/worker/local-worker-start.ts](https://github.com/stablyai/orca/blob/3cc5e1dac659ffd163b81b28261cd843261f4ca5/src/main/runtime/rpc/methods/orchestration/worker/local-worker-start.ts#L129) first resolves caller/worktree/agent configuration and creates starting dispatch, then calls worker placement/readiness/setup. [src/main/runtime/orchestration/db/worker-dispatch/worker-dispatch-start.ts](https://github.com/stablyai/orca/blob/3cc5e1dac659ffd163b81b28261cd843261f4ca5/src/main/runtime/orchestration/db/worker-dispatch/worker-dispatch-start.ts#L48) wraps task/dispatch/worker/mutation receipt in `BEGIN IMMEDIATE`. Receipt key is caller fingerprint plus request ID; a conflicting payload is refused. Worker starts at `starting/accepted` with persisted start options/runtime epoch; provider-start is a later observation. This is directly useful for Neokod's chat-to-Symphony acknowledgement: durable request accepted is its own result, not a spinner claiming the agent launched. Cost: crash/replay reconciliation needs a bounded stored stage machine, rather than a promise chain that exists only in memory.
2. Recovery preserves incomplete inventory. [src/main/runtime/runtime-restored-orchestration-authority-sweep.ts](https://github.com/stablyai/orca/blob/3cc5e1dac659ffd163b81b28261cd843261f4ca5/src/main/runtime/runtime-restored-orchestration-authority-sweep.ts#L10) retires authority only for hosts positively queried and PTYs absent from that completed inventory. Its caller [src/main/runtime/orca-runtime-refresh-pty-worktree-records-with-controller-inventory.ts](https://github.com/stablyai/orca/blob/3cc5e1dac659ffd163b81b28261cd843261f4ca5/src/main/runtime/orca-runtime-refresh-pty-worktree-records-with-controller-inventory.ts#L302) supplies queried/live sets. A failed provider list does not erase authority. Adapt the local principle only: an unavailable provider inventory is unknown, not an empty list proving no child survives. This does not establish full restart correctness, especially with the current issue below.
3. Bounded prompt admission. [src/shared/orchestration-worker-start-prompt-budget.ts](https://github.com/stablyai/orca/blob/3cc5e1dac659ffd163b81b28261cd843261f4ca5/src/shared/orchestration-worker-start-prompt-budget.ts#L19) derives byte admission from a fixed worker-start grace budget, reserves bytes for dispatch preamble, and checks oversized text with yielding. This is a transport/startup budget, not an LLM token budget. Build explicit Neokod prompt/context/result bounds separately; do not convert bytes to an invented provider token count.
4. Nested task lineage is persisted in the starting-dispatch transaction through creator dispatch, task parent and depth. That fits the requested parent/child workstream view. The source of the relationship is the server task/dispatch record, not a terminal title or inferred sidebar adjacency. [src/main/runtime/orchestration/db/worker-dispatch/worker-dispatch-start.ts](https://github.com/stablyai/orca/blob/3cc5e1dac659ffd163b81b28261cd843261f4ca5/src/main/runtime/orchestration/db/worker-dispatch/worker-dispatch-start.ts#L135)

Decision: adapt the transactional receipt/stage and inventory evidence ideas; build the chat presentation against Neokod contracts. Reject cloud/federation/mobile/SSH infrastructure and frontend porting. Gate adoption with process-kill after acceptance/before launch, duplicate retry, oversized Unicode prompt, surviving-child reconnect, and actual provider first-turn-start observations. Current reports distinguish idle/readiness/input acceptance from execution, which Neokod should preserve explicitly.

## CodexHost

Identity: [BytePioneer-AI/codex-host](https://github.com/BytePioneer-AI/codex-host), linked with its own product site/README/homepage. Source frozen at [49d8b1c6a3d70ca9ea2024d688e68847e66dd163](https://github.com/BytePioneer-AI/codex-host/commit/49d8b1c6a3d70ca9ea2024d688e68847e66dd163) (2026-10-04T05:18:57Z); licence: [LGPL-3.0](https://github.com/BytePioneer-AI/codex-host/blob/49d8b1c6a3d70ca9ea2024d688e68847e66dd163/LICENSE). The following paths describe the frozen default branch, not a claim about that released binary.

Three concrete paths:

1. Cross-harness child identity and idempotence. [packages/host-runtime/src/harness-delegation-coordinator.ts](https://github.com/BytePioneer-AI/codex-host/blob/49d8b1c6a3d70ca9ea2024d688e68847e66dd163/packages/host-runtime/src/harness-delegation-coordinator.ts#L206) resolves a parent, normalises cwd, hashes task/model/thinking, detects request-ID conflict, creates a provisional child and `creating` delegation record, opens the selected adapter, commits its native ref, starts turn and waits up to 10s for native identity persistence before returning running. Effective model/permission/thinking facts are stored from actual session state. The explicit request identity and native ref boundary are useful; the implicit 30s task dedupe is unsuitable for canonical Jira dispatch because two identical task descriptions can represent distinct issues. The source opens delegated external sessions with unattended full access: do not inherit that execution policy into Neokod's governed permissions.
2. Parent/child observation and native restore are separate from launch. [packages/host-runtime/src/external-thread-runtime.ts](https://github.com/BytePioneer-AI/codex-host/blob/49d8b1c6a3d70ca9ea2024d688e68847e66dd163/packages/host-runtime/src/external-thread-runtime.ts#L423) deduplicates concurrent restores in-process, resumes persisted native identity/configuration and checks unsupported permission restoration rather than inventing it. Restore registers an ordinary thread with no active turn until further state establishes activity. That makes #431 a valuable ownership warning: a new transport must consult a server-global writer lease/runtime fact, not consider a newly allocated object idle. Neokod already has generation/termination contracts; extend those shared boundaries, not a per-client runtime map.
3. Capabilities reflect the particular harness API. [docs/harnesses/capability-boundaries.md](https://github.com/BytePioneer-AI/codex-host/blob/49d8b1c6a3d70ca9ea2024d688e68847e66dd163/docs/harnesses/capability-boundaries.md) distinguishes outbound from unattended inbound delegation, native permission policy from tool filtering, real compaction from summary prompts, native reasoning choices from another model's options, and history file reads from live in-memory subagent registries. It explicitly declines Cursor inbound full-access capability where effective permission cannot be confirmed, and Pi permission modes without a native catalogue. Adapt this discipline to Neokod provider instances. Source docs' local runtime probes are their evidence, not proof on this workstation.

Decision: adapt native identity/configuration/capability contracts and request replay semantics. ## Traycer

Identity: [traycerai/traycer](https://github.com/traycerai/traycer), linked with its own product site/README/homepage. Source frozen at [745704377226b576d92b80ba421466e5c7a71fa9](https://github.com/traycerai/traycer/commit/745704377226b576d92b80ba421466e5c7a71fa9) (2026-10-04T02:10:40Z); licence: [MIT](https://github.com/traycerai/traycer/blob/745704377226b576d92b80ba421466e5c7a71fa9/LICENSE). The following paths describe the frozen default branch, not a claim about that released binary.

Four inspectable public paths, with the execution boundary explicit:

1. Reference, transcript read and message delivery are different capabilities. [mintlify/concepts/agent-to-agent.mdx](https://github.com/traycerai/traycer/blob/745704377226b576d92b80ba421466e5c7a71fa9/mintlify/concepts/agent-to-agent.mdx#L84) makes the distinction explicit and says parent hierarchy is provenance, not universal read/send authority. Receiver interface/provider determines whether incoming messages are supported. The same doc says cross-host messages can be accepted by cloud before receiving host consumes them. Adapt the capability distinction only; reject cloud delivery/sync and avoid treating a referenceable child as necessarily steerable.
2. Shared client/transport lifetime. [clients/gui-app/src/lib/host/owned-durable-stream-client.ts](https://github.com/traycerai/traycer/blob/745704377226b576d92b80ba421466e5c7a71fa9/clients/gui-app/src/lib/host/owned-durable-stream-client.ts#L13) opens transport then typed stream client, composes close of both, and closes partially opened transport on constructor throw. It is used by [clients/gui-app/src/lib/registries/chat-session-registry.ts](https://github.com/traycerai/traycer/blob/745704377226b576d92b80ba421466e5c7a71fa9/clients/gui-app/src/lib/registries/chat-session-registry.ts#L419) and terminal-session registry. Adapt narrow ownership/composition for Neokod local subscriptions if existing client runtime lacks that shared boundary. This inspected wrapper is not evidence all private provider streams drain, as #2254 warns.
3. Automatic restart does not kill a merely unresponsive live process. [clients/desktop/src/electron-main/startup/desktop-startup.ts](https://github.com/traycerai/traycer/blob/745704377226b576d92b80ba421466e5c7a71fa9/clients/desktop/src/electron-main/startup/desktop-startup.ts#L1143) builds [clients/desktop/src/electron-main/host/host-recovery-governor.ts](https://github.com/traycerai/traycer/blob/745704377226b576d92b80ba421466e5c7a71fa9/clients/desktop/src/electron-main/host/host-recovery-governor.ts#L120). Governor asks process existence, treats unverifiable liveness conservatively, backs off 0/60s/5m, trips after 5 consecutive grants and resets only after 5 minutes sustained health. Manual recovery stays a separate deliberate action. Adapt the structural single restart gate plus incarnation/liveness evidence. Trade-off: a permanently wedged live server requires user recovery; automatic restart cannot infer safe termination from endpoint timeout.
4. Worktree busy evidence and acknowledgement contracts are richer than a boolean. [protocol/src/framework/worktree-busy-holders.ts](https://github.com/traycerai/traycer/blob/745704377226b576d92b80ba421466e5c7a71fa9/protocol/src/framework/worktree-busy-holders.ts#L58) describes holders for actual turn, runnable queue, native child/workflow and other background work; missing tier means unknown-busy, not idle. [clients/traycer-cli/src/host/update-dispatch-ack.ts](https://github.com/traycerai/traycer/blob/745704377226b576d92b80ba421466e5c7a71fa9/clients/traycer-cli/src/host/update-dispatch-ack.ts#L14) stamps atomic nonce-correlated ack after durable claim and represents claimed/no-attempt separately. These are public protocol/CLI facts; private Host receiver semantics are not independently inspectable. Adapt typed local owner inventory and durable acceptance ordering, not Traycer's cross-host/update pipeline.

The public repository [CONTRIBUTING.md](https://github.com/traycerai/traycer/blob/745704377226b576d92b80ba421466e5c7a71fa9/CONTRIBUTING.md#L3) explicitly contains clients, CLI and protocol; releases are built in an internal repository. It has no execution Host source to trace dispatch idempotence, provider stream consumption, backend recovery, shared memory persistence or deterministic validation. MIT applies to the public files, not an assumed right to unavailable backend. The README's broader orchestration claims do not fill that gap.

Decision: adapt the inspectable capability/lifetime/evidence ideas and build backend invariants within Neokod. Conditional evaluation of anything requiring Host behaviour needs additional source or black-box runtime evidence; no substitute similarly named repository was used. Reject cloud sync/team transport/remote/mobile infra. Gates: late follow-up durable acceptance must be independent of provider cold resume; valid recovery identity must target the same sender/receiver; resource ownership must close/drain local streams; large transcript/artifact hydration cannot stall mutation service or silently revive stale queues.
